What this viewer read and checked

Asking the reader…

Checked in this browser

Every file is rebuilt from its chunks and checked back to the root: each chunk against its record and its chunk id, each chunk-tree node and directory node against its id, each file against its file CID, each directory against its directory CID. A compressed file is decoded here and its content must hash to the value in its file CID. A reply that fails a check is refused and the next endpoint is asked, so an endpoint cannot change a file under a known root.

Taken from the endpoints

A project's current root is read from the project's token. No hash covers that answer, so every endpoint listed above is asked at the same block: at least two must answer and all that answer must agree. A root address (one that starts with "r") names its root in the hostname and needs no such answer.

The viewer's own code is served by this hostname's web server; everything it shows comes from the chain. A project's own service worker does not run here, and a project folder named _abxfs cannot be opened.

Your own endpoint

By default the files are read through public endpoints run by other people. If you run a node, or trust one endpoint, name it here: it is asked first. With "only this one" nothing is asked of any other server, and the rule that two endpoints must agree on a project's current root is replaced by your trust in yours.

The viewer itself

The viewer's own code comes from this address's web host and is the one thing here that is not checked against the chain. This is the build the reader is running. The same files, built from the repository with tools/build-view.py, give the same hashes on any host. Once a project has been opened, the reader and these pages keep working if the host goes away.

Kept in this browser

Only raw replies from the chain are kept, so a later visit asks for less. They are not trusted: a project's own scripts can write this address's storage, so every kept reply goes through the same checks as a fresh one each time it is used.
