What this viewer read and checked

Asking the reader…

Checked in this browser

Every file is rebuilt from its chunks and checked back to the root: each chunk against its record and its chunk id, each chunk-tree node and directory node against its id, each file against its file CID, each directory against its directory CID. A compressed file is decoded here and its content must hash to the value in its file CID. A reply that fails a check is refused, so an endpoint cannot change a file under a known root.

Taken from the endpoints

A project's current root is read from the project's token. No hash covers that answer, so every endpoint listed above is asked and all that answer must agree. A root address (one that starts with "r") names its root in the hostname and needs no such answer.

The viewer's own code is served by this hostname's web server; everything it shows comes from the chain. A project's own service worker does not run here, and its links to wallets and other sites work as they would anywhere.
