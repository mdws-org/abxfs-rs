What this page does

A project's files are checked against its root wherever they are shown. Which root is the project's current one is a separate question, and this page answers it two ways and compares the answers.

By proof: starting from a block built into this viewer, it follows Ethereum's sync committee to a recent finalized block, checking each signature, and reads the project's root out of that block's state with a Merkle proof. No server is believed along the way. By agreement: it asks several public endpoints for the root, at that same block and at the newest block.

Finality runs about a quarter of an hour behind. A version published since then cannot be proved yet, and is reported as such.

This page is on its own address, which a project's scripts cannot change. A project's page can show any words it likes, including these; only the page whose address begins with check. is this one. The proof rests on two things: the starting block built into this viewer, and at least two thirds of each sync committee since then being honest. Committee members are not penalised for signing a false block.

The starting block

A proof starts from one block root. One is built into this viewer and is replaced each week. You can give one of your own for : a finalized block root from a beacon node or a checkpoint provider you trust, no older than 14 days. Then nothing here rests on the built-in one. This page cannot tell where your block root came from. It counts only when the sync committee's signatures lead from it to a newer finalized block.

Built in:

Checkpoint-sync services publish a recent finalized root. Several run independently of each other: sync-mainnet.beaconcha.in, mainnet.checkpoint.sigp.io, beaconstate.ethstaker.cc, mainnet-checkpoint-sync.stakely.io and sync.invis.tools. Each one's /checkpointz/v1/status page gives it under "finalized". This page cannot read them itself (they do not allow it), so compare two or three and paste the root.

Your own nodes

A consensus node with the light client routes turned on, and an execution node, are asked before the public ones. They are only asked for data: what they return is checked like any server's. A browser asks a node from this page only at an https address, or at http on localhost, and only when the node allows requests from other sites.
